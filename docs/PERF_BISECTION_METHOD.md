# 二分法切除：性能瓶颈定位方法论

> 引擎吞吐（EPS）不达标或回归时，用「逐段切除管线」定位瓶颈段——而不是一上来就
> 猜热点 / 上 profiler。切除法给出**段的边界**，热点采样给出**段内的函数**，
> 两者结合收敛最快。本方法沉淀自一次 NEXMark 吞吐回归定位（输出链 -38%、
> 规则 -12%、注入供给三面墙），内容不依赖具体负载，可迁移到任何基准。

## 0. 机制化：诊断模式

> ✅ **已定稿**：本方法论已内建为引擎诊断模式机制，见
> [`docs/design/perf-diag-mode-design.md`](design/perf-diag-mode-design.md)。
> 诊断定位 = 声明式切换诊断档（不重启 daemon、不改代码、不手拼测量）：
>
> | 本文刀法 | 机制诊断档 | 载体 |
> |---|---|---|
> | ① 切输出 | `full` vs `rules` 档 | `[perf].cut_output` 原子门控 |
> | ② 切规则 | `rules` vs `floor` 档 | `[perf].cut_rules` 原子门控（ack 保留） |
> | 规则子集 | `family_*` 档 | `runtime.rules` hot reload |
> | ④ 预算 | `budget:X` 档（唯一重启例外） | `parse_buffer_bytes` |
> | 计时 | `profiling=off` | `WF_RULE_PROFILING=0`（启动期环境变量，非诊断档） |
> | 完成信号 | 漂流瓶 sentinel `__wf_sentinel` | 哨兵任务等数据窗排空后写 `perf_sentinel{round,n,start_ns,emit_ns}` + `stage{current=k}` 记录 |
>
> 驱动：`wfgen perf-diag --diag conf/perf-diag.toml --frames ... --n-list ...`
> （逐档切 → 发帧+哨兵 → 读哨兵文件 → 墙表）。本文以下各节的方法论细节
> （叠加式切除、CPU% 忙/等判别、裸环境测速、防坑清单）仍然适用，是诊断档落地
> 时的操作手册。

## 1. 适用场景

- 单查询 / 全量 EPS 不达标或相对历史基线回归
- 需要回答「瓶颈在注入 / 解码 / 窗口 / 规则 / 输出哪一段」
- 改动后吞吐异常（提升或回退），需要归因

## 2. 核心原则

1. **一次只切一段**，保留可测指标：基准的 appended 追平 + EPS + CPU% + RSS。
2. **从管线尾部向前切**（输出 → 规则 → 窗口 → 解码 → 注入）：尾部段先排除；
   切到窗口 append 本身会让基准无法收敛（无消费者 ack）。
3. **叠加式切除**：每把刀在前一刀的状态上切（① 切输出 → ② 再切规则），
   逐步逼近最前端的墙。
4. **用 CPU% 区分「忙墙」和「等墙」**：
   - CPU 高（>500%）且切段后大幅下降 → 该段是 CPU 密集热点（如输出 serialize）。
   - CPU 低（<40%）但吞吐受限 → 同步 / IO / 供给墙（等数据、等 ack、磁盘读速），
     **profiler 采到的是等待栈，不是热点函数**。
5. **每刀记录 load（负载）**：开发机后台负载波动会把 EPS 拉低 20%+，
   无负载上下文的对比不可信。

## 3. 管线模型

```
注入（客户端读盘 → TCP）→ daemon recv → decode（Arrow IPC）
  → 窗口 append（actor）→ 规则（each / match / close / stats）
  → 输出（构建→通道 → sink 物化+序列化+写）
```

每段的度量：

| 段 | 度量 |
|---|---|
| 注入供给 | 客户端独立推速、`dd` 读帧速、连接数并行 |
| decode | 微基准（标准解码 vs 免校验解码对拍耗时） |
| 窗口 append | 窗口内存（积压 = 规则消化跟不上） |
| 规则 | 切规则（空规则文件）前后 EPS 差 |
| 输出 | 切输出（无 sink）前后 EPS 差；输出速率 vs 输入速率 |

## 4. 切除刀法清单（大多无需改引擎代码）

| 刀 | 做法 | 切断 | 实现 |
|---|---|---|---|
| ① 切输出 | 移走 benchmark 的 sink 组 | serialize+stage+commit+fanout | 改拓扑配置 |
| ② 切规则 | 规则文件换成空规则（只留 `use`） | 规则处理整段 | 改 wfl |
| ③ 切解码校验 | 热路径改用免校验解码（skip validate） | Arrow `validate_values`（UTF-8 全量校验） | 改引擎 |
| ④ 预算 | `parse_buffer_bytes` 1GB / 2GB / 4GB | preread 预算槽位 | 改配置 |
| ⑤ 读粒度 | TCP read 缓冲 + `SO_RCVBUF`（需 vendored 依赖） | read 循环粒度 | 改依赖 |
| ⑥ 连接并行 | 单连接 / 多连接 | 注入并行（读盘 + source 实例） | 改环境 |
| ⑦ 磁盘/缓存 | `dd` 测读速、预热文件缓存、释放内存 | 供给物理墙 | 环境 |

## 5. 辅助定位工具

1. **CPU 采样**（macOS `sample` / Linux `perf`）：
   ⚠ **采样窗口必须覆盖活跃期**——空态注入很短，采样开始太晚会采到收尾 idle
   （全是 park）。等输入计数开始增长后再采。
2. **指标时间序列**：输入速率、输出速率、窗口内存。**注意口径**——指标常是区间
   差值（rate），取末尾残留值是 0，不代表没输出。
3. **微基准**：对疑似热点写对拍 / 计时测试，隔离确认（如免校验解码快 n 倍）。
4. **裸环境测速**（排除/坐实供给墙）：
   - 裸 TCP 单连接吞吐 → 排除网络；
   - `dd` 读帧文件 → 磁盘读速（单连接供给墙的常见上限）；
   - 客户端独立推 + 接收端计数确认 → 客户端是否瓶颈（推速 = 读盘速则不是）。
5. **字节测算**：`EPS = 字节速率 ÷ 每事件字节`。先测数据帧每事件字节，再算
   字节墙对应的事件数上限——数字上直接闭合，避免猜。

## 6. 输出列式化的收益边界（规律，非 case）

切除法定位出「输出链是墙」后，是否值得做输出列式化，取决于**输出字段的来源**：

| 路径 | 字段来源 | 列式化收益 |
|---|---|---|
| each 无 join | Arrow 列 | **最大：免每事件 Event 物化（零物化）** |
| each + join | 左窗列 + join 富化 | 大（列式 join 富化已接） |
| match 命中 | 已物化在上下文中（scope_key / 触发事件） | 小：仅省 OutputRecord 构造 + append |
| close / conv / stats | 已物化 `CloseOutput` | 小：仅构造层 |

规律：

1. **纯输出型查询**（字段还在列里）→ 列式化收益最大（零物化）。
2. **状态机查询**（match/close）→ 输出列式化只解构造段；主瓶颈通常在
   **状态机 advance / join / 单 worker 串行 / 状态内存**。列式化后剩余热点是
   `wfx_id` 这类**每命中固有成本**（哈希 scope_key + step_data），省不掉。
3. **有 fmt / General yield 的规则** → 门控回退行式（fmt 是每记录字符串格式化，
   列式化无收益）。
4. **判断优先级**：先采样确认该查询「输出构造」占忙侧比例——比例低则输出列式化
   收益有限，应转向状态压缩 / 并行分片。

## 7. 常见坑

1. **采样错过活跃期**：空态注入很短，采样太晚全是 idle park。
2. **指标口径**：区间差值 ≠ 累计；残留末尾 0 不代表没输出。
3. **负载波动**：对比必须带 load，否则无法区分「改动效果」与「环境波动」。
4. **历史数字口径**：历史基线需"当时环境/数据/配置"三要素齐全才可复现；
   数据版本、连接数、内存状态任一变化都会使旧数字失真。
5. **大 staging 栈数组**：TCP read 缓冲从小值直接放大到数 MB 会让平台
   `read` 异常（数据不流动、输入计数为 0）；应配合 socket 接收缓冲逐步调。
6. **并行参数的作用域**：source 实例并行是**连接级** round-robin，单连接只激活
   1 个实例——多配实例对单连接无效（先确认并行参数的作用域再调）。
7. **改动必须验证生效**：加开关 / 列式化后必须确认路径真的走了（采样看到新函数）。
   输出批处理若按"每命中一次锁"实现，高频命中时反而更慢——应**批级累积**
   （move 进批级 Vec，零拷贝）后统一处理。
8. **对照实验区分「改动」与「环境」**：回退特定文件（`git stash` pathspec）
   构建，同一环境测「有/无改动」基线；不要拿历史数字当基线。
